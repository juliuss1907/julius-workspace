# Workflow — Coin68 Content Writer

Step-by-step process for writing Coin68 articles.

**Version:** 2.0
**Last updated:** 2026-05-26
**Changes from v1.0:** Added Phase 0 (SEO Brief), meta description in frontmatter, internal linking step, SEO-aware heading guidance.

---

## Phase 0: Read SEO Brief

Before starting research, read the SEO brief generated by `seo-optimizer/` skill.

### Step 0.1: Load SEO brief

The SEO brief contains:
- **Keywords:** Primary, secondary, and long-tail (query fan-out) keywords
- **Title:** Recommended optimized title (use as H1)
- **Meta description:** 150-160 char description (use in frontmatter)
- **Competitor analysis:** Gaps found in published articles of the same category
- **Content angle:** Recommended focus areas for differentiation

### Step 0.2: Note key inputs for drafting

From the SEO brief, extract and keep in mind:
- The recommended H1 title (use exactly or adapt slightly)
- The meta description (copy to frontmatter `description` field)
- Secondary keywords to weave into H2/H3 headings naturally
- Content gaps from competitor analysis (ensure new article covers these)
- Suggested content angle (emphasize recommended differentiators)

**If no SEO brief is available:** Proceed with default workflow. Use the standard title format `[Project] là gì? Tìm hiểu về [description]` and write a meta description manually following the template in Step 3.1.

## Phase 1: Read Research Dossier

### Step 1.1: Load Research Dossier

Research Dossier từ `source-researcher/` skill chứa:
- Project overview (name, category, blockchain, type)
- Project type flags (has token? incubated? foundation? pre-mainnet?)
- Key metrics + verification status (✅ ⚠️ ❌)
- Sources used + date accessed
- Cross-links found (for "Có thể bạn quan tâm" section)
- Gaps (sections còn thiếu info)
- Reference article patterns (H2/H3 structure, terminology from same category)

### Step 1.2: Review gaps & plan sections

Based on dossier:
- Sections with ✅ data → write normally
- Sections with ⚠️ data → write with caveat, note source may be outdated
- Sections with ❌ data → write "Thông tin chưa được công bố công khai"
- Project type flags → decide which optional sections to include:
  - Has token → include Tokenomics section
  - Incubated → mention parent company in Đội ngũ
  - Pre-mainnet → emphasize roadmap, testnet stats

**If no Research Dossier available (standalone mode):**
→ Follow `source-researcher/SKILL.md` workflow to gather sources yourself before proceeding.

## Phase 3: Draft

### Step 3.1: Write frontmatter

Use the title and meta description from the SEO brief. If no SEO brief is available, write them manually.

```yaml
---
title: "[Project] là gì? Tìm hiểu về [short description]"
description: "[150-160 char meta description with primary keyword + value proposition]"
source: "https://coin68.com/[project-slug]-la-gi/"
created: YYYY-MM-DD
tags:
  - "[category-tag]"
---
```

**Meta description guidelines:**
- 150-160 characters
- Include project name (primary keyword) naturally
- Include core value proposition
- Specific and informative, not generic
- Vietnamese, formal tone

**Example:**
```yaml
---
title: "Variational là gì? Tìm hiểu về giao thức phái sinh phi tập trung đa tài sản"
description: "Variational là giao thức phái sinh phi tập trung tổng hợp thanh khoản từ crypto và TradFi. Tìm hiểu sản phẩm, đội ngũ và tokenomics của dự án."
source: "https://coin68.com/variational-la-gi/"
created: 2026-05-22
tags:
  - "perp-dex"
  - "infrastructure"
---
```

### Step 3.2: Write H1 title

Use the recommended title from SEO brief. If no brief available, follow this format:

Format: `[Project] là gì? Tìm hiểu về [short description]`

**SEO constraints:**
- Primary keyword ("[Project]") at the beginning
- < 60 characters (Google truncates beyond this)
- Include core value proposition in description part
- Keep crypto-native terms in English

Examples:
- `Phoenix là gì? Tìm hiểu về fully on-chain perp DEX trên Solana`
- `PrismaX là gì? Tìm hiểu về hạ tầng dịch vụ cho robotics`
- `Pixie Chess là gì? Tìm hiểu về game cờ vua Web3 trên blockchain Base`

### Step 3.3: Write "là gì?" section

2-3 sentences:
1. What the project is (category + blockchain)
2. Core value proposition
3. Key differentiator (optional)

Example:
```markdown
## Phoenix là gì?

Phoenix là perp DEX được xây dựng hoàn toàn trên blockchain Solana bởi Ellipsis Labs. Với kiến trúc fully on-chain và sử dụng matching engine kép kết hợp sổ lệnh FIFO truyền thống với Spline liquidity độc quyền, Phoenix mang đến trải nghiệm giao dịch perpetual futures với tốc độ và hiệu quả vốn cao.
```

### Step 3.4: Write "Điểm nổi bật" section

List 3-6 key features as H3 subsections.

**Feature selection criteria:**
- Technical innovations (architecture, consensus, novel mechanisms)
- User benefits (lower fees, faster transactions, better UX)
- Ecosystem advantages (partnerships, integrations, network effects)

**Feature writing pattern:**
```markdown
### [Feature name in Vietnamese]

[1-2 paragraphs explaining the feature]
[Include technical details if relevant]
[Explain user benefit]
```

### Step 3.5: Write optional sections

**"Sản phẩm chính" or "Cơ chế hoạt động":**
- Use when project has multiple products/components
- Each component gets H3 subsection
- Explain how components work together

**"Vòng lặp kinh tế" or "Các cách tham gia":**
- Use for projects with complex tokenomics or user flows
- Explain the flywheel or participation mechanisms

### Step 3.6: Write "Đội ngũ phát triển"

Format:
```markdown
## Đội ngũ phát triển

[Project] được phát triển bởi [Company/Team Name], do [Founder Name] sáng lập.

[Optional: 1-2 sentences about founder background]

[Optional: Notable team members with relevant experience]
```

If team is anonymous or minimal info available:
```markdown
## Đội ngũ phát triển

Đội ngũ phát triển [Project] hoạt động dưới dạng pseudonymous, tập trung vào việc xây dựng sản phẩm và cộng đồng thay vì branding cá nhân.
```

### Step 3.7: Write "Nhà đầu tư"

Format:
```markdown
## Nhà đầu tư [và đối tác]

[Project] đã huy động được [amount] trong vòng [round name] do [lead investor] dẫn đầu, với sự tham gia của [other investors].

[Optional: Notable partnerships or integrations]
```

If no funding info:
```markdown
## Nhà đầu tư

Thông tin về nhà đầu tư của [Project] chưa được công bố công khai.
```

### Step 3.8: Write "Tokenomics" (if applicable)

Only include if project has a token. Format:
```markdown
## Tokenomics

**Token:** [Symbol]
**Tổng cung:** [Total supply]
**Phân bổ:**
- [Category 1]: [percentage]
- [Category 2]: [percentage]
- [Category 3]: [percentage]

[Optional: Vesting schedule, utility, governance]
```

### Step 3.9: Write "Tổng kết"

2-3 sentences wrapping up:
1. Restate core value proposition
2. Current status or next milestone
3. Neutral closing (no investment advice)

Example:
```markdown
## Tổng kết

Phoenix là một perp DEX fully on-chain trên Solana với kiến trúc matching engine độc đáo, hướng tới mục tiêu mang đến trải nghiệm giao dịch perpetual futures nhanh chóng và hiệu quả vốn cao. Dự án hiện đang trong giai đoạn testnet và dự kiến ra mắt mainnet trong Q2/2026.
```

### Step 3.10: Write "Có thể bạn quan tâm" section

Add an internal linking section after "Tổng kết" to link to 2-3 related published Coin68 articles. This improves topical authority and helps both readers and search engines discover related content.

**Format:**
```markdown
**Có thể bạn quan tâm:**

- [Related Project 1 là gì? Tìm hiểu về ...](https://coin68.com/related-project-1-la-gi/)
- [Related Project 2 là gì? Tìm hiểu về ...](https://coin68.com/related-project-2-la-gi/)
```

**How to select related articles:**
1. Read `working/Coin68/contents/published/published.md` for category index
2. Find 2-3 published articles in the **same category** (e.g., same tag: perp-dex, defi, layer-1)
3. Prefer articles about projects that are:
   - Direct competitors (same category, same blockchain)
   - Complementary projects (same ecosystem, different function)
   - Related concepts (if a concept article exists)

**Rules:**
- Use descriptive anchor text (the full article title, not "click here")
- Link to the published Coin68 URL (https://coin68.com/...), not the local file path
- Only link to articles that actually exist in the published/ folder
- Place this section **after Tổng kết** but **before** the verification block

**Example (for a perp-dex article):**
```markdown
**Có thể bạn quan tâm:**

- [Hyperliquid là gì? Tìm hiểu chi tiết về sàn phái sinh trên blockchain](https://coin68.com/hyperliquid-la-gi/)
- [Perpetual Protocol (PERP) là gì? Tìm hiểu về giao thức phái sinh trên Ethereum](https://coin68.com/perpetual-protocol-la-gi/)
```

## Phase 4: Verification

### Step 4.1: Fact-check

Go through article line by line:
- [ ] Every number has a source
- [ ] Every claim about team/investors is verified
- [ ] Technical terms are used correctly
- [ ] No speculation presented as fact

### Step 4.2: Terminology check

- [ ] English terms kept where appropriate (perp DEX, not "sàn giao dịch vĩnh viễn")
- [ ] Vietnamese terms used correctly (huy động vốn, not "raise capital")
- [ ] No awkward translations

### Step 4.3: Neutrality check

Remove or rephrase:
- [ ] Hype language ("revolutionary", "game-changing")
- [ ] Investment advice ("should buy", "good opportunity")
- [ ] Unverified superlatives ("best", "fastest", "most secure")

### Step 4.4: Structure check

- [ ] All required sections present
- [ ] Heading hierarchy correct (H1 → H2 → H3, no skips)
- [ ] Logical flow (intro → features → team → conclusion)
- [ ] Length appropriate (1000-2000 words for Review)

---

## Phase 5: Proofread

### Step 5.1: Grammar and spelling

- [ ] Vietnamese grammar errors
- [ ] Typos
- [ ] Punctuation
- [ ] Consistent terminology

### Step 5.2: Formatting

- [ ] Frontmatter complete (title, description, tags, created)
- [ ] Meta description 150-160 chars
- [ ] Bold used correctly (project name first mention, key numbers)
- [ ] Bullet points formatted consistently
- [ ] Internal linking section present ("Có thể bạn quan tâm")
- [ ] No markdown images
- [ ] No emoji
- [ ] Code blocks only for code (not for emphasis)

### Step 5.3: Final read

Read the entire article as if you are a Coin68 reader:
- Does it answer "What is [Project]?"
- Is it informative without being promotional?
- Would you understand the project after reading?

## Error Handling

### If source material is insufficient

Escalate with specific gaps:
```
Cannot complete article for [Project] due to missing information:
- Team: No founder info on website or LinkedIn
- Investors: Claimed [X] raised but no announcement found
- Tokenomics: Whitepaper mentions token but no distribution details

Options:
A. Proceed with available info, note gaps in article
B. Wait for Julius to provide additional sources
C. Skip sections that lack info (if optional)
```

### If project category is unclear

Check `working/Coin68/contents/published/published.md` for existing categories. If no match, escalate:
```
[Project] does not fit existing Coin68 categories.
Suggested new category: [your suggestion]
Or closest match: [existing category]
```

### If deadline is impossible

Escalate immediately with realistic timeline and options:
```
Task deadline: [date]
Estimated time needed: [X hours] for research + [Y hours] for writing
Reason: [explain complexity]

Options:
A. Extend deadline to [new date]
B. Reduce scope (shorter article, fewer sources)
C. Prioritize over other tasks
```
